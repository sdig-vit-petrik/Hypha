# hypha 0.4.0 (not released)

Notes collected for the next release line; the summary is written when it is cut.

## Breaking changes and upgrade

- **Several triggers (#206).** `hypha_cycle_set_trigger` and `Cycle::setTrigger` add a
  trigger on each call instead of replacing the trigger; `abi.revision` goes from 6 to
  7. Under simulated time a triggered step at T waits until every upstream reported T,
  not T − 1 ns (execution-model.md §6.6).
- **Topic names under `/hypha/` (#132).** `/hypha` and every topic name under `/hypha/`
  are the framework's and refused with `InvalidTopic`, except `/hypha/intercept/` (the
  state of `hypha intercept`). 0.3.0 refused only `/hypha` itself. The transport keeps its
  services there, and a topic `/hypha/srv/x` shared the server lock of service `/x`.
  Rename such a topic (`/hypha/text` to `/bridge/text`, for example); a ROS bridge
  route's `hypha_topic` follows the same rule.
- **Node manifest.** `hypha_msgs/IntrospectedCycle.trigger` (a topic) becomes
  `triggers` (a list of topics, in port order), which changes the schema hash of
  `IntrospectedCycle` and of `NodeIntrospection`: a 0.3.0 tool does not read the
  `~/introspection` of a 0.4.0 node, and the reverse; a recorded `~/introspection` of
  0.3.0 does not decode as the new type.
