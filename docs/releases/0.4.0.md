# hypha 0.4.0 (not released)

Notes collected for the next release line; the summary is written when it is cut.

## Breaking changes and upgrade

- **Services (#132, stage 1b).** A plain node or an `ApplicationNode` serves and calls a
  `.srv`: `Node::advertiseService<Srv>()`, `Node::serviceClient<Srv>()` (with
  `hypha::blocking` for a worker thread, a test or a tool), `hypha::Request`,
  `hypha::Deferred`, `hypha::CallResult` (`hypha/service.h`, `hypha/service_client.h`;
  cpp-api.md §8). Ten C functions are new (`hypha_service_server_create`,
  `hypha_service_server_destroy`, `hypha_request_answer`, `hypha_request_defer`,
  `hypha_request_destroy`, `hypha_service_client_create`, `hypha_service_client_destroy`,
  `hypha_client_call`, `hypha_client_status`, `hypha_client_wait_for_server`);
  `abi.revision` goes from 11 to 12. The SDK ships `std_srvs` (`Empty`, `Trigger`,
  `SetBool`): an application that declared its own `std_srvs` with
  `hypha_generate_messages()` drops that call, as the MRS and Autoware examples did. A
  generated service header gains `TYPE_NAME`.
- **Standard services under their ROS names (#315).** The SDK ships the services of the
  ROS 1 Noetic packages whose messages it ships, unchanged, so their MD5 is ROS's:
  `nav_msgs/GetMap`, `GetPlan`, `LoadMap`, `SetMap`; `sensor_msgs/SetCameraInfo`;
  `diagnostic_msgs/AddDiagnostics`, `SelfTest`; `tf2_msgs/FrameGraph`. A port that renamed
  one (`map_server_msgs/GetMap`, `arena_camera_msgs/SetCameraInfo`) uses the SDK's and drops
  its copy. `hypha_generate_messages(PACKAGE sensor_msgs ...)` with the name of a package
  of the SDK now adds the application's own messages and services to it, beside the SDK's
  (the target is `sensor_msgs_additions`; a definition of a name the package has is
  refused); it failed before ("both the generated package and a dependency"). The
  generator takes `--base-dir` for it. The Rust `hypha_msgs` has the types of every
  service (`hypha_msgs::nav_msgs::GetMap`, `GetMapRequest`, `GetMapResponse`) with
  `TYPE_NAME` and `MD5`.

- **Wire frame `IOX7` (#255).** The frame header carries `payload_len`, the message's
  bytes within the sample's slice, in what were four bytes of padding (the header stays 56
  bytes), and the CRC covers it. The magic goes from `IOX6` to `IOX7`: a 0.3.0 and a 0.4.0
  process refuse each other's frames as `InvalidFrame` (interface-specification.md, Wire
  frame). It lets a typed loan send fewer bytes than it reserved.
- **Typed loan (#255).** `hypha_publisher_reserve_frame`, `hypha_loan_shrink` and
  `HYPHA_STATUS_LOAN_LIMIT` are new; `abi.revision` goes from 9 to 10.
- **A transform buffer with no node (#248).** `hypha_transform_buffer_create_fed` and
  `hypha_transform_buffer_feed` are new; `abi.revision` goes from 10 to 11.
  `testing::StepHarness::deliver(Transforms&, ...)` and `deliverStatic()` feed a step
  test's `Transforms` port through it; a lookup in a harness step threw before.
- **Several triggers (#206).** `hypha_cycle_set_trigger` and `Cycle::setTrigger` add a
  trigger on each call instead of replacing the trigger; `abi.revision` goes from 6 to
  7. Under simulated time a triggered step at T waits until every upstream reported T,
  not T − 1 ns (execution-model.md §6.6).
- **Topic names under `/hypha/` (#132).** `/hypha` and every topic name under `/hypha/`
  are the framework's and refused with `InvalidTopic`, except `/hypha/intercept/` (the
  state of `hypha intercept`). 0.3.0 refused only `/hypha` itself. The transport keeps its
  services there, and a topic `/hypha/srv/x` shared the server lock of service `/x`.
  Rename such a topic (`/hypha/text` to `/bridge/text`, for example); a ROS bridge
  route's `hypha_topic` follows the same rule.
- **Node manifest.** `hypha_msgs/IntrospectedCycle.trigger` (a topic) becomes
  `triggers` (a list of topics, in port order), which changes the schema hash of
  `IntrospectedCycle` and of `NodeIntrospection`: a 0.3.0 tool does not read the
  `~/introspection` of a 0.4.0 node, and the reverse; a recorded `~/introspection` of
  0.3.0 does not decode as the new type.
- **A stream for each schema of a topic (#209).** A topic name carries one stream per
  message type and per version of a type (its MD5), each an iceoryx2 service of its own
  named `<topic>@<schema hash>`: a 0.3.0 node and a 0.4.0 node do not see each other's
  topics at all. `HyphaServicePortInfo` gains `schema_hash` and the listing reports each
  stream; `abi.revision` goes from 8 to 9. `subscribeRawOfType` takes a `hypha::RawType`
  instead of a type name, since its MD5 selects the stream. A subscription that names no
  MD5 reads the streams that exist when it is created and no longer creates the topic.
  A frame of another MD5 on a topic is no `schema_mismatch` any more, and two MD5s on one
  name have their own policies (two type names of one definition still share one). `hypha_msgs/RequiredInput` gains `data_type` and `md5`
  and `IntrospectedEndpoint` gains `md5`, which changes the schema hash of `NodeState` and
  `NodeIntrospection` again. The MD5s: `RequiredInput` 36176747… → 30435d9760612081c47a9b675d2b5ef8,
  `NodeState` 3f764952… → 029d88fdad9e1e251e936acef2caa3f1, `IntrospectedEndpoint` ffe5f5ae… →
  5083f17ee1ec38babf25e19e40990950, `NodeIntrospection` f50b4d7b… →
  52d9cd223657ce58a341d3710dd9e3f7. The review rounds added `RequiredInput.other_schemas_checked`
  and `RequiredInput.other_schemas` (`hypha_msgs/TopicSchema[]`, a new message,
  `67f9f8ff0c78fa31752269ba082f283f`), so `RequiredInput` is
  `03d9c09e2155a1201b5ca928b9717fdf` and `NodeState` `912221931c7910c5b8618cd343f7e413`.
  `HyphaSubscriberCounters` gains `other_schemas` (`HYPHA_NOT_CHECKED` before a check): 72
  bytes instead of 64, a layout change inside revision 9, which this line introduces; the
  C++ SDK checks the size at compile time. Every endpoint that names an MD5 now writes its
  stream's record, an empty one without a definition, so the 126-byte limit of a topic name
  that held for an endpoint with a definition holds for one without too (an untyped
  endpoint keeps 238). The graph event also fires when a publisher is created or dropped,
  so every node of a domain wakes once per endpoint at a start; each starts at most one
  refresh round per 100 ms. A refresh opens another stream for a moment and takes one of
  its node slots; a stream keeps 2 beyond its endpoints for that and for the check of its
  record when an endpoint drops, so no endpoint is refused for it. A node start that reclaims a dead node removes the records of the streams
  that are gone.
  built on the earlier definitions sees a node's `~/state` and `~/introspection` carry a
  schema hash it does not know and shows no state or manifest for the node (`hypha node
  info` reads the node registry and is unaffected); a recording keeps the definition it
  was made with.
- **The tools follow each stream of a topic name (#209).** `hypha record` writes one MCAP
  channel for each stream, with its own schema, and records a stream that joins a followed
  name later: a second type or version on a name is no longer dropped with an error, and
  `--sync` no longer fails on it. `hypha play` publishes each stream of a topic on its own
  publisher, and under `--clock` counts the chunk and queue rules per stream. `hypha topic
  echo`, `hz` and `bw` follow every stream of the name, label each when the name has several
  (`# type (md5 start)`, a title line), print a header for each stream under `echo -p`, and
  take `--type` and `--md5` to choose. `hypha top` shows a row for each stream, an input's
  type and MD5, and its `other_schemas` (`not checked`, `none`, or the versions). The ROS 1
  bridge's automatic mode bridges the first stream of a name and says once that it drops the
  others. They follow a stream that appears later on the graph event; the SDK gains
  `BusNode::graph_watch`, `BusNode::subscribe_raw_stream` and `StreamFollower`. A stream
  keeps 2 node slots beyond its endpoints (`max_nodes` + 2) for a probe and a release check.
  A stream that joins a followed name after a recording began is recorded from the moment it was followed, and `hypha record` tells how many samples it sent before (`--sync` fails on them, and on a stream that refuses its subscription); `echo -p` refuses a name with several streams and names them. The counts of `hypha play` and `hypha record` lines are per stream, and `hypha record`
  prints `Following <n> stream(s)` where it printed `Following <n> topic(s)`.
