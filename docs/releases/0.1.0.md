# hypha 0.1.0

Released 2026-11-19 (`b7cc33c`). The first release: a single-host shared-memory data
plane for mixed C++ and Rust robotics components. `abi.revision` is 1.

These notes were written after the release, on 2026-11-21, from the release commit;
0.1.0 had no release notes and no release policy.

## What it contains

- **The core and its C ABI.** A memory-safe Rust core over `iceoryx2` shared memory,
  exposed as one C ABI shared library, `libhypha_ffi`
  ([interface-specification.md](../interface-specification.md)).
- **The C++ SDK** (C++23) over that ABI: nodes, publishers and subscribers, timers,
  cycles with `Latest` and `Arrivals` inputs and input supervision, TOML parameters,
  logging, and `runNode` ([cpp-api.md](../cpp-api.md)).
- **The Rust SDK**, `hypha_node::sdk`, over the same runtime.
- **Communication.** Peer-to-peer topic discovery with no master; ROS 1 payload
  serialization with MD5 schema identity; latched topics; a raw loan path that
  publishes in place.
- **Frame checks.** Every frame carries a header (magic `IOX6`, publisher id,
  sequence, send times) and a CRC-32C over the header fields and the payload. A
  subscriber refuses a frame that fails a check and counts it
  ([communication-integrity.md](../communication-integrity.md)).
- **Message generation.** `hypha_msggen` generates C++, Rust and Python types from
  `.msg` and `.srv` files; `hypha_generate_messages()` does it in an application's
  CMake build.
- **Tools** ([tools.md](../tools.md)): `hypha topic`, `top`, `node`, `record` and
  `play` (MCAP), `launch`, `param`, `intercept`, `foxglove`, and the ROS 1 bridge
  `hypha_ros_bridge`.
- **Examples**: `bench`, `large_payload`, `mrs`, `scan_cycle`, `sensor_fusion`,
  `sensor_pipeline`, `sim_twin` and `speed`.
- **Images.** `docker/build.sh` builds the `builder` and `runtime` images for the
  architecture of the host.
- **Documentation**: the requirements specification (51 requirements), architecture,
  interface specification, execution model, C++ API, tools, getting started, the ROS 1
  migration guide and the deployment guide.

## Verification

The repository gates: `check.sh`, `test.sh` (the Rust and C++ suites and the installed
SDK), coverage of the core crates with a per-crate 80 % line gate, Miri over the Rust
tests without transport, and the fuzz targets. There was no qualification report and
no CI job beyond `check.sh` and `test.sh` on amd64.

## Platforms

Ubuntu in the builder image, on amd64 and arm64. macOS was a development platform
without a guarantee.

## Known limits

- A frame that reaches a subscriber of another topic with the same type passes its
  checks: the CRC does not cover the topic. The documents of 0.1.0 state it (insertion
  and masquerade are outside the design). 0.2.0 detects it with the topic-bound checksum.

## Support

None: before 1.0.0 a release line receives no fixes once the next one is released
([release-policy.md](../release-policy.md) §6). Upgrade to 0.2.0
([0.2.0.md](0.2.0.md), breaking changes and upgrade).
